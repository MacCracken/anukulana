# anukulana Audit Report — 2026-11-09

**Scope:** a P(-1) hardening, optimization and repair sweep over the whole repository outside vendored `lib/`:
`src/` (about 2,500 lines), `tests/`, the Makefile, the CI and release workflows, and the documents.
**Baseline:** 1.2.1 (cyrius 6.7.18, sigil 3.13.15, tula 1.6.1, rosnet 1.4.1, rupantara 0.5.3).
**Result:** 1.2.2. For valid input every output is bit-identical to 1.2.1.

## Executive summary

**Two HIGH defects, both in the foreign importers, both a crash on a hostile file:**

- **safetensors: a tensor's shape was never compared with its payload.** `st_open` checked
  `0 ≤ o0 ≤ o1 ≤ data_len` but not that the shape's bytes fit between them, and `st_read_f64` reads as many
  elements as the shape says. `shape [1e8]` over 4 payload bytes was accepted, and reading it ran 400 MB past
  the buffer (SIGSEGV). The importer reaches it: `_gpt2_copy` checked the shape's element count, then read.
- **GGUF: an oversized weight overflowed a heap scratch.** `_ggpt2_mat_t` widened the whole source tensor into
  a scratch sized for the largest expected weight (F·C) and only checked that the tensor had *enough* output
  rows. An `attn_qkv.weight` with F + 4096 rows wrote 256 KB past the scratch (SIGSEGV).

**Six MEDIUM defects:** GGUF element counts that wrap; a GGUF u16 KV read with a 4-byte load (a 2-byte
over-read, reached inside `gg_open` itself); signed checkpoints and adapters read without checking their
tensors' dtype or size; both GPT-2 mappings checking element counts instead of shapes (a transposed weight
was imported silently); an operator-key file accepted at any length ≥ 64 and with mismatched halves; and the
CLI's decode loop growing the heap on every token (filed by rupantara's 2026-11-09 audit).

The rest is LOW hardening, resource leaks, CLI hygiene, test and CI gaps, and documentation drift. The import
hot paths are 1.4–2.4× faster with the same bits, and three copies of the demo training code are now one.

## Method

- **Toolchain sweeps (6.7.18), baseline then final:** `cyrius test` on every suite, plus `--bounds` and, a
  first for this repo, `--aarch64` (qemu-aarch64); `cyrius lint` and `--strict --strict-deferrals`;
  `cyrius fmt --check`; `cyrius vet`; `cyrius deny`; `cyrius doc --check` (28 public fns undocumented → 0);
  `cyrius coverage` (48/69 → 60/84 fns referenced); `cyrius audit` ("no benchmarks" → bench found);
  `cyrius deps --verify` / `--locked`.
- **Manual review** of every line of `src/`, the suites, the Makefile and both workflows, and the
  cross-repo notes about anukulana in rupantara's, tula's and rosnet's audits and roadmaps.
- **Reproduction on the 1.2.1 code.** Every finding below marked *repro* was demonstrated with a probe built
  against the unmodified 1.2.1 tree before it was fixed. The three crashes were run to the signal.
- **Mutation testing.** 15 mutants, each reverting one fix, all killed by the 1.2.2 suites. The first pass
  left two alive (the dim-1 half of the safetensors shape check; the oracle's V cap); each got a test.
- **Fuzz upgrade check.** The upgraded `tests/tcyr/fuzz.tcyr` passes on 1.2.2 and kills the 1.2.1 code
  (SIGSEGV).
- **Benchmarks:** `tests/anukulana.bcyr` (new). 1.2.1 and 1.2.2 on the same host and session, median of 3.

## Findings

### HIGH — fixed

| # | Finding | Where | Fix |
|---|---|---|---|
| 1 | **safetensors shape never compared with payload.** *Repro:* `shape [1e8]` over `data_offsets [0,4]` accepted; `st_read_f64` on it → SIGSEGV. The importer's `_gpt2_copy` compared only the shape's element count. | `src/safetensors.cyr` | `st_open` requires every dim to be a non-negative JSON integer, multiplies them with an overflow check (cap 2^56), and requires a fixed-width tensor to occupy exactly shape × element-size bytes — for every such dtype, read or not (U8, I32, …). Offsets must be integers. 13 directed assertions; fuzz now reads every accepted tensor. |
| 2 | **GGUF scratch overflow.** *Repro:* `attn_qkv.weight` with F + 4096 output rows → `anuk_ggpt2_pack` wrote past its F·C scratch, SIGSEGV. | `src/gpt2_gguf.cyr` | Every weight must have exactly its expected `ne = [in, out]`. |---|---|---|

(no checkpoint on the verification host), so the end-to-end gain on the real model is projected, not measured.

### Refactor

- **One batch-vs-decode runner** (`anuk_decode_check` + `_anuk_run_check`) instead of two 40-line copies in
  `main.cyr`.
- **One head adapter** (`anuk_head_adapter_new / _fwd / _fwd_with / _train`) instead of three copies of its
  17 allocations and 800-step Adam loop in `lora_demo`, `qlora_demo` and `tula_demo`; plus
  `anuk_demo_tokens / _targets` and `anuk_argmax_matches` (five copies). `tests/tcyr/lora.tcyr` holds the
  shared trainer bit-identical to a verbatim copy of the 1.2.1 loop (A, B, step-0 and final loss, logits).
- **`tests/common.cyr`**: the safetensors and GGUF writers and both GPT-2 exporters, moved out of two suites.

## Observations — not changed, and why

- **The HF-fidelity gate and the checkpoint demos were not run**: no GPT-2 checkpoint on the verification
  host. The import changes are held bit-identical by the round-trip, widener and refactor-equivalence tests,
  but `make fidelity` has not been re-run since 1.1.3.
- **Duplicate tensor names in a safetensors header**: the first match wins. The spec forbids duplicates;
  detecting them is O(n²) over a hostile header.
- **GGUF tensor offsets are not checked for alignment.** Unaligned loads are safe on both targets.
- **Unknown and sub-byte safetensors dtypes** (F4, F6) are listed with no size contract and never read.
- **New public helpers in a patch.** `st_read_f64_range`, `st_entry_nbytes`, `gg_read_f64_range`,
  `anuk_decode_check`, the head adapter and the demo helpers are documented as out-of-freeze; they freeze at
  the next minor, per `STABILITY.md`'s "additions land as minors".
- **The oracle and `gpt2-cross` still call the allocating `ru_model_fwd`**: 3 and 2 calls, bounded.
- **`inspect` reads through `tula_read_file`** (a private copy, 2 GiB cap) rather than a mapping: fine for
  anukulana's 63.8 MB artifacts, and safer for files someone else may be writing.
- **Key hygiene beyond the format checks** (file permissions, wiping the loaded key at exit) stays the
  caller's, per tula's charter.
- **`--bounds` and `--aarch64` are not CI steps** (run time); both were run here, all 219 assertions green.
- **The CI installer comes from cyrius `main`**, as across the ecosystem; pinning it is a cross-repo decision.
- **The run-length repack** (`anuk_gpt2_import` re-packs per `T_run`) waits on rupantara's `ru_model_fwd_n`.

## Downstream

anukulana is a binary; nothing links it. For valid input every output is bit-identical to 1.2.1. Malformed
input that crashed or was silently mis-imported is now rejected. CLI changes: errors on stderr, exit 2 for an
unknown command or option, `gpt2-cross` checks every config field. `anuk_sk_load` rejects key files that are
not exactly a consistent seed‖pk pair.
